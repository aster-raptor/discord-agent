目的:
Telegram の新着会話を読み、投資判断に有用な注目対象と、前回要約からの変化を抽出してください。
注目対象には、サービス、プロトコル、取引所、銘柄、テーマを含めて構いません。

今回の依頼:
{user_request}

比較ルール:
- Local input の `前回の記憶` は比較用の過去要約、`前回以降の新着メッセージ` は今回の主判断材料です。
- `前回の記憶` にある文章を、今回の新着発言や今回の根拠として扱わないでください。
- 前回からの変化を `new`（新規）、`strengthened`（強まった）、`weakened`（弱まった）、`reversed`（方向が反転）、`resolved`（明示的に解消）に分類してください。
- 新着で言及されなかったことだけを理由に、弱まった・解消したと判断しないでください。
- 変化を裏付ける新着発言がなければ、該当配列は空にしてください。
- 前回の記憶がない初回は `baseline_available` を false にし、比較不能であることを明記してください。

このタスクで重視すること:
1. 何が話題の中心なのか
2. なぜ注目されているのか
3. 参加者の温度感が強気・弱気・中立・混合のどれに近いか
4. その話題を受けて、トレーダーや投資家が何を確認・監視すべきか

最重要ルール:
- 主判断は必ずチャット内容に基づいてください。外部知識は補助的な文脈整理に限ります。
- 事実と推測を分けてください。会話に書かれていないことを断定しないでください。
- 根拠が薄い対象を無理に重要扱いしないでください。
- 根拠が弱い、意見が割れている、文脈が不足している場合は `confidence` を `low` にしてください。
- 不明な点は埋めずに、「チャット上では不明」と扱ってください。
- 雑談、内輪ネタ、明らかなノイズは `noise_topics` に分離してください。

抽出ルール:
- 表記ゆれ、英字/カナ、略称を統合して `normalized_name` を付けてください。
- 単なる一言言及ではなく、会話頻度、反応の強さ、具体性、価格材料性、イベント性を見て重要度を判断してください。
- `services` には重要度順に最大 8 件まで入れてください。重要な対象が少ない場合は無理に埋めず、少数で構いません。
- イベント性が高い話題を優先してください。例: 上場、TGE、資金流入、出来高急増、入出金停止、ハック、買い戻し、資金調達、エアドロ、vault、oracle 問題など。
- `attention_score_0_to_100` は絶対評価ではなく、このチャット内での相対評価として付けてください。
- `why_people_care` は「なぜこの対象が話題になっているか」を短く具体的に書いてください。
- `recommended_actions` はチャットから自然に導ける監視・確認アクションのみを書いてください。根拠が弱ければ空配列で構いません。
- `bullish_reasons` と `bearish_reasons` は、会話中に示唆があるものだけを書いてください。なければ空配列で構いません。

根拠の扱い:
- すべての `services` 要素に `evidence` を付けてください。
- `evidence` は `{timestamp, speaker, quote}` の配列にしてください。
- 根拠は最大 3 件までに絞り、短くても会話のニュアンスが分かる引用を選んでください。
- タイムスタンプや発言者がログ上で取れない場合は、分かる範囲だけ入れ、捏造しないでください。

出力順序:
1. 最初に JSON を 1 つだけ返す
2. JSON の後に、人間向け要約を日本語で付ける

JSON 要件:
- トップレベルは次のキーを持つこと
  - `services`
  - `market_summary`
  - `changes_since_previous`
  - `action_plan`
  - `noise_topics`
- `services` の各要素は次のキーを持つこと
  - `name`
  - `normalized_name`
  - `category`
  - `attention_score_0_to_100`
  - `sentiment`
  - `bullish_reasons`
  - `bearish_reasons`
  - `why_people_care`
  - `recommended_actions`
  - `confidence`
  - `evidence`
- `market_summary` は、市場全体または会話全体のセンチメントを 2-4 文で要約する
- `changes_since_previous` は次のキーを持つこと
  - `baseline_available`（boolean）
  - `new`
  - `strengthened`
  - `weakened`
  - `reversed`
  - `resolved`
- `new` / `strengthened` / `weakened` / `reversed` / `resolved` は短い説明の文字列配列にする
- `action_plan` は次の 3 キーを持つこと
  - `immediate`
  - `intraday`
  - `swing`
- `immediate` / `intraday` / `swing` は文字列または文字列配列でよい
- `noise_topics` は重要でない話題の文字列配列にする

フィールド解釈:
- `category` は例として `DEX`, `CEX`, `L1`, `L2`, `Infra`, `DeFi`, `Meme`, `AI`, `Macro`, `Theme` などを使ってよい
- `sentiment` は `強気`, `弱気`, `中立`, `混合` のいずれかを優先する
- `confidence` は `high`, `medium`, `low` を使う

人間向け要約の要件:
- JSON の後に日本語で短い要約を付けてください
- 次の 4 セクションに分けてください
  1. `要約`
  2. `前回からの変化`
  3. `主要ポイント`
  4. `次に見るべき点`
- `要約` ではチャット全体の空気感と最重要対象を簡潔にまとめる
- `前回からの変化` では5分類のうち該当する変化だけを簡潔に示してください。
- 初回は、比較できる前回の記憶がないことを記載してください。
- `主要ポイント` では重要対象 Top 3 を中心に、理由と温度感を箇条書きで書く
- `次に見るべき点` では `immediate` / `intraday` / `swing` に対応する監視項目を書く

失敗しやすい点:
- JSON の前に説明文を書かない
- 会話にない価格水準、ファンダ数値、日付、イベント確度を作らない
- 前回の記憶だけを根拠に今回の変化を断定しない
- 単に今回言及がないだけの話題を、弱まった・解消したと判定しない
- すべての対象を強引に bullish / bearish に寄せない
- ノイズと主要論点を混ぜない
- 根拠不足の対象に `high` confidence を付けない

{local_input_section} を読み、新着会話の注目対象と前回からの変化を抽出してください。
